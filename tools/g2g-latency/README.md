# Glass-to-Glass 지연 측정 도구 (#19)

현장 폰 카메라 렌즈 앞에서 일어난 일이 전문가 PC 화면에 보이기까지 걸린 시간을 잰다. getStats의 RTT는 네트워크 왕복만 보여 주므로, 사용자가 실제로 느끼는 지연은 이 도구로 잰다 (TD-12).

## 원리

```
PC 화면 왼쪽: G2G 시계 (지금 시각을 QR로)  ──폰 카메라로 찍음──>  현장 폰  ──WebRTC──>  PC 화면 오른쪽: 전문가 화면
                                                                                       받은 프레임의 QR을 읽는다
G2G 지연 = 그 프레임이 전문가 화면에 표시되는 시각 - QR 속 시각
```

- 시계와 전문가 화면이 **같은 PC**에 있으므로 두 시각이 같은 시계다. 폰과 PC의 시계를 맞출 필요가 없다.
- 표시 시각은 `requestVideoFrameCallback`의 `expectedDisplayTime`, 수신 시각은 `receiveTime`(WebRTC)을 쓴다. 그래서 지연을 두 구간으로 나눠 볼 수 있다.
  - 받기 전 = 수신 시각 - 시계 시각: 시계 화면 표시, 카메라 노출과 처리, 인코딩, 네트워크
  - 받은 뒤 = 표시 시각 - 수신 시각: 지터 버퍼, 디코딩, 화면 표시
- QR 읽기는 Chrome의 `BarcodeDetector`. 없으면 jsQR을 CDN에서 불러온다.

## 파일

| 파일 | 내용 |
|---|---|
| `clock.html` | G2G 시계 페이지 (`/tools/g2g-latency/clock.html`) |
| `clock.js` | 시계 그리기. 현장 시험 모드 `?fake=clock`의 영상 소스로도 쓴다 |
| `g2g.js` | 측정기. 전문가 화면의 '종단 지연 측정'이 불러 쓴다 |

## 실제 측정 절차 (T4, #22)

1. PC에서 서버와 터널을 켠다 (`npm start`, `npm run tunnel`).
2. PC Chrome에서 전문가 화면을 화면 오른쪽 반에, `clock.html`을 왼쪽 반에 띄운다. 시계 창은 QR이 크게 보이게 키운다.
3. 폰에서 현장 화면을 열고 카메라를 켠다. 폰을 고정하고 후면 카메라가 시계 QR 전체를 비추게 한다(거리 20~40cm).
4. 전문가 화면의 '종단 지연 측정'을 펼쳐 **측정 시작**. 표본이 100개 이상 쌓이면 **측정 중지** > **측정값 저장 (CSV)**.
5. 같은 조건에서 품질 기록 CSV도 저장한다. 결과는 `experiments/YYYY-MM-DD_T4-.../`에 둔다.

## 수동 검증

자동 측정값이 맞는지, 두 화면을 **한 사진**에 담아 확인한다.

1. 다른 폰(또는 같은 폰의 다른 카메라 앱이 아니라 별도 기기)으로 PC 화면 전체를 찍는다. 시계 숫자와, 전문가 화면 속 영상에 찍힌 시계 숫자가 한 사진에 같이 들어가야 한다.
2. 사진에서 `왼쪽 시계 숫자 - 전문가 화면 속 시계 숫자`를 계산한다. 이것이 그 순간의 G2G 지연이다.
3. 5장 이상 찍어 평균을 내고, 자동 측정 중앙값과 비교한다. 차이가 아래 오차 범위 안이면 도구를 믿을 수 있다.

## 오차 요인

| 요인 | 크기 | 방향 |
|---|---|---|
| 시계 화면 갱신 간격 | 60Hz 모니터면 최대 16.7 ms | 시계 숫자는 그리기 시작 시각이라 실제 화면에 나오는 것은 다음 갱신 때다. 측정값이 그만큼 크게 나온다 |
| 카메라 노출 시간 | 실내 조명에서 수 ms ~ 33 ms | 한 프레임이 노출되는 동안 시계가 바뀌면 QR이 번져 못 읽는다(못 읽음 수로 확인) |
| 카메라 프레임 간격 | 15 fps면 66.7 ms | 시계가 바뀐 직후에 찍혔는지 직전에 찍혔는지에 따라 표본이 흩어진다. 중앙값과 p95로 본다 |
| 표시 시각 추정 | `expectedDisplayTime`은 예정 시각 | 실제 화면 출력과 수 ms 차이 가능 |
| QR 읽기 시간 | 프레임당 수 ms ~ 수십 ms | 측정값에는 들어가지 않는다(표시 시각을 먼저 기록). 읽는 동안 온 프레임은 건너뛴다 |

## 시험 모드 `?fake=clock`

현장 화면 주소에 `&fake=clock`을 붙이면 카메라 대신 이 시계를 그린 캔버스를 바로 보낸다. 카메라와 모니터 구간이 빠지므로 **인코딩, 네트워크, 지터 버퍼, 디코딩, 표시**만의 지연이 나온다. 실제 G2G와의 차이가 곧 카메라와 시계 화면 구간이다.

자동 시험(`npm run e2e`)이 이 모드로 측정기를 확인한다. PC 한 대, Chrome 두 개, 가짜 연결에서 8초 동안 표본 108개, 중앙값 49 ms, 못 읽음 0이었다.
