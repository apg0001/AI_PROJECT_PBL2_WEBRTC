# DESIGN.md - 디자인 기준

> 기준은 하나만 쓴다: Anthropic `frontend-design` 스킬 (`.claude/skills/frontend-design/SKILL.md`, Apache 2.0).
> 이 문서는 그 스킬의 절차(주제에서 출발 → 토큰 계획 → 기본값 검토 → 제작 → 자기 비평)를 이 프로젝트에 적용한 결과다.
> 웹 화면, 보고서 다이어그램, 발표자료 꾸밈이 모두 이 문서를 따른다. 발표자료는 사용자 템플릿이 우선이다(§6).

## 1. 주제 · 대상 · 할 일

- **주제:** 공장 설비가 고장 났을 때 현장 작업자의 폰과 원격 전문가의 PC를 실시간으로 잇는 원격 지원.
- **대상**
  - 현장 작업자: 폰 하나, 한 손 또는 장갑, 소음, 공장 조명이나 햇빛 아래의 화면.
  - 원격 전문가: 책상 앞 PC, 영상을 오래 들여다본다.
  - 과목 멘토와 평가자: 보고서와 발표로 구조와 근거를 읽는다.
- **화면마다 할 일**
  - 현장 화면: 지금 연결됐는지 한눈에 알고, 전문가 지시를 놓치지 않는다.
  - 전문가 화면: 영상을 보며 지시하고, 연결 품질을 확인한다.
  - 다이어그램: 신호와 영상이 어디로 흐르는지 보인다.

## 2. 주제에서 가져온 표현

디자인 재료는 이 주제의 현장에서 가져온다.

| 현장의 물건 | 쓰는 곳 |
|---|---|
| **설비 점검 태그** (노란 꼬리표에 굵은 검은 글씨) | 현장 화면의 연결 상태 표시 하나에만 쓴다 |
| **배관·전기 계통도** (선의 종류와 굵기가 뜻을 가지고, 기기는 기호와 이름표로 그림) | 다이어그램. 박스 카드 대신 기호와 선 |
| **작업 지시서·점검표** (칸이 그어진 양식, "항목 / 값" 행) | 연결 정보 표, Room 번호 |
| **안전 색** (KS A ISO 3864: 노랑 주의, 초록 안전, 빨강 정지) | 색은 이 뜻으로만 쓴다 |

## 3. 토큰

### 색

| 이름 | 값 | 뜻과 쓰임 |
|---|---|---|
| 종이 | `#FFFFFF` | 배경 |
| 먹 | `#22272B` | 본문 글자, 주요 선 |
| 강철 | `#5F6B76` | 보조 글자, 보조 선 |
| 눈금 | `#D5DADF` | 표의 칸 선 |
| 점검 노랑 | `#F5C400` | 주의·대기. 점검 태그 바탕. 그 위 글자는 먹 |
| 연결 초록 | `#1B7A47` | 연결됨, 영상·데이터가 흐르는 경로 |
| 정지 빨강 | `#B42318` | 실패, 끊김 |

- 색은 위 뜻으로만 쓴다. 꾸미기 위한 그라디언트·색 배경·그림자는 쓰지 않는다.
- 밝은 배경 하나로 고정한다. 다크 모드는 두지 않는다 (공장 조명과 햇빛 아래 폰 가독성 우선).

### 글꼴

- **IBM Plex Sans KR** 한 가지 (400, 600). 산업·엔지니어링 맥락에서 만들어진 글꼴이라 설비 매뉴얼의 말투와 맞고, 한글을 지원한다.
- 숫자는 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다.
- 고정폭 글꼴은 실제 주소·코드 값(ICE 후보 주소, 명령어)에만 쓴다. 라벨에는 쓰지 않는다.
- 크기 단계(px): 13 · 15 · 17 · 20 · 24 · 30 · 38. 현장 화면 본문 17, 전문가 화면 본문 15.

### 레이아웃

- 왼쪽 정렬. 가운데 정렬은 쓰지 않는다.
- 구분은 여백과 표의 칸 선으로 한다. 같은 모양의 둥근 카드로 내용을 쪼개지 않는다.
- 모서리 반경은 2px 하나 (입력칸·버튼). 정보 묶음에는 상자를 두르지 않는다.

```
현장 화면 (폰)                    전문가 화면 (PC)
┌──────────────────────┐          ┌───────────────────────────────┬──────────────┐
│ ▌연결됨              │ 점검태그  │ 현장 영상 (2주차)              │ 연결됨       │
│  Room 4F-ab12        │          │                               │ ─────────── │
├──────────────────────┤          │                               │ 경로   직접  │
│ 카메라 화면 (2주차)   │          │                               │ 연결   46 ms │
│                      │          │                               │ 왕복    9 ms │
├──────────────────────┤          ├───────────────────────────────┤ ─────────── │
│ 받은 지시            │          │ 지시 보내기 (2주차)            │ [ping][나가기]│
│ 연결 정보  ▸ 펼치기   │          │ 연결 기록 ▸ 펼치기             │              │
└──────────────────────┘          └───────────────────────────────┴──────────────┘
```

## 4. 원칙

1. **대담함은 한 곳에만:** 현장 화면의 점검 태그(상태 표시). 나머지는 조용하게.
2. **상자와 선은 정보일 때만:** 표의 칸, 계통도의 선처럼 뜻이 있을 때만 긋는다.
3. **색은 안전 색의 뜻으로만:** 노랑 대기·주의, 초록 연결, 빨강 실패.
4. **말은 쓰는 사람의 말로:** "연결됨", "전문가를 기다리는 중", "다시 연결하는 중". ICE·srflx 같은 기술 용어는 전문가 화면의 연결 정보와 연결 기록 안에서만, 쉬운 말을 붙여 쓴다.
5. **움직임은 상태가 바뀔 때만:** 점검 태그 색이 바뀌는 것 하나. 들어올 때 미끄러지는 효과 같은 장식 움직임은 없다.

## 5. 기본값 검토

스킬이 꼽은 'AI가 만든 디자인에 몰리는 특징'과 대조한 결과다.

| 특징 | 이전 결과물 | 바꾼 것 |
|---|---|---|
| 크림 배경 + 세리프 + 테라코타 | 해당 없음 | - |
| 거의 검은 배경 + 밝은 강조 1색 | 웹 화면이 시스템 설정에 따라 `#121212` 어두운 화면으로 바뀜 | 밝은 배경 고정 |
| 신문식 가는 선 + 각진 모서리 + 빽빽한 단 | 해당 없음 | 표에만 선을 쓰고, 단을 빽빽하게 나누지 않는다 |
| 같은 모양 둥근 카드, 같은 그림자, 그라디언트 | 다이어그램 전체, 슬라이드 4장, 시작 화면 링크 | 계통도 기호와 표로. 카드 제거 |
| 템플릿 장식: 가운뎃점(A · B · C) 나열, 문장 앞 '→', 고정폭 작은 라벨, 대문자 라벨, 짙은 회색 '검정' | 다이어그램, 슬라이드, 웹 화면 곳곳 | 모두 제거. 화살표는 그림 안의 실제 흐름에만 |
| 한 단어만 색으로 강조 | 슬라이드 결론을 주황색으로 | 결론은 색 없이 굵게(발표 규칙상 결론 문장은 유지) |

**거울 검사:** 다른 사람이 비슷한 원격 지원 화면을 요청해도 같은 결과가 나오는가? 점검 태그와 계통도 표현은 '공장 설비 지원'이라는 이 주제에서만 나오므로 통과로 본다. 기본값처럼 보이던 것(보라색 시그널링 선, 둥근 카드, 어두운 화면)은 위 표대로 바꿨다.

## 6. 매체별 적용

- **웹 화면** (`client/`): `client/css/app.css`의 `:root`에 위 토큰을 두고, 그 밖의 곳에 색·글꼴 값을 직접 쓰지 않는다.
- **다이어그램** (`docs/diagrams/src/`): `base.css`에 같은 토큰. 계통도 규칙:
  - 기기(폰, PC)는 기호와 이름표, 서버와 외부 서비스는 각진 사각형(먹 1.5px 선).
  - 선의 뜻: 시그널링 = 먹 점선, 영상·데이터 = 연결 초록 굵은 실선, STUN 질의 = 강철 점선(짧은 점), TURN 중계 = 점검 노랑 긴 점선.
  - 범례는 계통도처럼 한 칸에 모은다.
- **발표자료** (`weekly/`): 사용자 템플릿(동국대 랩미팅)이 우선이다. 템플릿 글꼴(맑은 고딕)과 장식은 그대로 두고, 그 안에서 위 원칙 2·3·4와 §5의 장식 제거만 적용한다.
